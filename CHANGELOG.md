# Changelog

All notable changes to `@bpc-oss/dsh-verification` (and companion packages
`@bpc-oss/dsh-evidence`, `@bpc-oss/dsh-client-ui-verification`) are documented here.

## [1.0.0] - 2026-08-18

Initial open-source release. The verification engine ported from
[Bobby](https://github.com/bpc-oss/bobby): in DeepSeek Harness (DSH), "claimed
done" and "actually done" become structurally equivalent — every acceptance
criterion must be backed by server-stamped, real tool evidence before the
completion gate lets a goal through.

### Added

- **Verification engine** (`@bpc-oss/dsh-verification`):
  - `set_verification_plan` / `get_verification_plan` / `reset_verification_plan` tools
  - goal-bound task epochs, frozen selectors (tool + args hash), content-addressed
    evidence blobs, T0–T4 oracles, completion gate + durable completion permits
  - `advisory` (record, never-deny) and `enforce` (block unverified completion) modes
- **Evidence domain** (`@bpc-oss/dsh-evidence`): pure zod schemas for contracts,
  evidence, verdicts, selectors, source basis
- **Client UI** (`@bpc-oss/dsh-client-ui-verification`): settings panel for
  verification state
- **Benchmarks** (`pnpm --filter @bpc-oss/dsh-verification bench`): 12 synthetic
  scenarios (8 planted defects + 4 clean) — recall 100%, false-positive 0%
- **Real-task evaluation**: `scripts/real-task-benchmark.py` (session replay audit)
  and `scripts/task-completion-eval.py` (false-rejection detection on real data)
- **CI**: GitHub Actions (typecheck + build + unit tests + benchmark +
  dist-pack reproducibility check) — green on every push
- **Value report**: `docs/value-report.md` with real-session replay data

### Fixed

- **Dock clutter**: removed the verification card from the conversation input
  area (was rendering AC/verdict/evidence text between the goal bar and the input)
- **History load failure**: `VerdictSchema.claimId` allowed empty for legacy
  no-evidence verdicts; new no-evidence verdicts write `ac.id` as the claim
- **Write-tool lockout** (`missing_authority_scope`): task epochs are now created
  for agent/UI-created goals (previously fail-closed when no user message
  preceded the goal); `getPlanView` degrades gracefully instead of throwing,
  so advisory mode never hard-blocks tools
- **False rejection of genuine completions**: `binderFamilyFallback` (default on)
  lets file-family ACs use real same-family evidence (file_diff/file_exists/
  quote_with_location) when the exact frozen selector yields no usable evidence
- **Actionable errors**: missing-epoch / missing-contract errors now include
  workflow guidance; README documents the recommended workflow and troubleshooting

### Changed

- `getPlanView` returns null instead of throwing when no task epoch is active
- `bindSelectorForAc` accepts a `familyFallback` option; `evaluateGate` re-judges
  file-family ACs with the fallback, noting it in the verdict detail
- `set_verification_plan` description + system prompt now guide selectors to match
  the actual work tools (prefer write/edit → file_diff over glob/read)

### Security notes

- Exact-only selector binding remains the default; family fallback is opt-out
  (`binderFamilyFallback: false`) for strict deployments
- Evidence payloads are content-addressed; blob missing/corrupt → fail closed
- Completion permits are durable and replayed with strict envelope authority

### Migration

- Existing sessions with a stale plan and no active task epoch now load and run
  in advisory mode without tool lockout
- `lib/` is regenerated by `pnpm -r build`; committed `dist-pack/*-fixed.tgz` are
  the reproducible publish artifacts (verified by CI)
